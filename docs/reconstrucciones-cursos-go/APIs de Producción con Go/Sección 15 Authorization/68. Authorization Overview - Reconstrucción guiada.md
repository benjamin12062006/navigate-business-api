## Objetivo de la lección

Definir una política simple y extensible antes de crear tablas y middleware.

## Fase 1 — Distinguir errores

Procedencia: E1.

```text
sin identidad válida → 401 Unauthorized
identidad válida sin permiso → 403 Forbidden
```

## Fase 2 — Política de recursos

Procedencia: E2.

```text
si user.ID == resource.OwnerID → permitir
si no → exigir role.level >= requiredRole.level
```

Un propietario controla su recurso. Para recursos ajenos, moderator puede actualizar y admin puede actualizar o eliminar según la ruta.

## Fase 3 — Modelo inicial

Procedencia: E3.

```text
users.role_id → roles.id

roles:
  user      nivel 1
  moderator nivel 2
  admin     nivel 3
```

## Código final completo de la lección

No aplica: la clase define la política. La migración aparece en 69 y la middleware en 70.

## Límite explícito

El instructor considera que roles cubren la mayoría de sistemas simples. Un CMS u otro dominio con permisos muy finos puede justificar `permissions → roles → users`; no debe añadirse por anticipación.

## Resumen mental

Primero comprobar propiedad; después comparar el nivel requerido. El modelo empieza pequeño y conserva un camino hacia permisos más granulares.
