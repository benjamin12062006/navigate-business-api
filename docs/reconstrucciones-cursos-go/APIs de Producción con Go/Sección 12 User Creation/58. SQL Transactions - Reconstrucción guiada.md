## Objetivo de la lección

Convertir “crear usuario e invitación” en una única operación atómica y preparar un token de invitación que no quede expuesto en la base de datos.

## Fase 1 — Wrapper reusable

Procedencia: E1.

```go
package store

import (
	"context"
	"database/sql"
)

func withTx(
	db *sql.DB,
	ctx context.Context,
	fn func(*sql.Tx) error,
) error {
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer tx.Rollback()

	if err := fn(tx); err != nil {
		return err
	}
	return tx.Commit()
}
```

## Fase 2 — Operaciones internas que reciben la transacción

Procedencia: E2, E3.

```go
func createUserInvitation(
	ctx context.Context,
	tx *sql.Tx,
	tokenHash string,
	userID int64,
	expiresIn time.Duration,
) error {
	_, err := tx.ExecContext(ctx, `
		INSERT INTO user_invitations (token, user_id, expiry)
		VALUES ($1, $2, $3)
	`, tokenHash, userID, time.Now().Add(expiresIn))
	return err
}
```

Usar `tx.ExecContext` es parte del contrato de atomicidad. Llamar `db.ExecContext` abriría una operación fuera de la transacción.

## Fase 3 — Crear, invitar y devolver el token plano

Procedencia: E2, E4.

```go
func (s *UserStore) CreateAndInvite(
	ctx context.Context,
	user *User,
	expiresIn time.Duration,
) (string, error) {
	plainToken := uuid.NewString()
	digest := sha256.Sum256([]byte(plainToken))
	tokenHash := hex.EncodeToString(digest[:])

	err := withTx(s.db, ctx, func(tx *sql.Tx) error {
		if err := s.create(ctx, tx, user); err != nil {
			return err
		}
		return createUserInvitation(ctx, tx, tokenHash, user.ID, expiresIn)
	})
	if err != nil {
		return "", err
	}
	return plainToken, nil
}
```

El token plano se envía al usuario; solo su hash se almacena.

## Fase 4 — Migración de expiración

Procedencia: E4.

```sql
-- up
ALTER TABLE user_invitations
ADD COLUMN expiry TIMESTAMPTZ NOT NULL;

-- down
ALTER TABLE user_invitations
DROP COLUMN expiry;
```

## Código final completo de la lección

Los tres bloques Go y la migración forman el mecanismo completo reconstruido. Se omiten estructuras del proyecto anterior que la transcripción no vuelve a definir.

## Límites

- La lección mezcla métodos siempre transaccionales y métodos duplicados con/sin `*sql.Tx`; no impone una regla universal.
- `defer tx.Rollback()` después de un commit exitoso es seguro: el rollback devuelve el error de transacción ya cerrada y se ignora.
- Esta guía no afirma que la transacción cubra el envío de correo; ese efecto externo requiere compensación, no rollback SQL.

## Resumen mental

La atomicidad existe solo si todas las consultas usan el mismo `*sql.Tx`. El wrapper reduce repetición, pero la operación compuesta sigue expresando el límite transaccional.
