# 25. Part 1: Layered Architecture — Reconstrucción guiada

Fuente primaria: [25. Part 1 Layered Architecture.md](./25.%20Part%201%20Layered%20Architecture.md)

Nivel de certeza: alto para la estructura; esta lección crea carpetas y el entrypoint, mientras la implementación llega en la siguiente.

## Mapa de procedencia

| ID | Pasaje | Evidencia recuperada |
|---|---|---|
| E1 | líneas 13-17; buscar `trip service` | el servicio tendrá varios transportes y suficiente lógica para justificar capas |
| E2 | líneas 17-27; buscar `CMD` | `cmd` contiene entrypoints; `internal` contiene dominio, infraestructura y servicio |
| E3 | líneas 27-33; buscar `infrastructure` | repository y handlers son adaptadores; service implementa lógica; tipos compartibles se separan |

## Objetivo de la lección

Crear únicamente el armazón que necesita un servicio complejo antes de implementar sus contratos.

## Fase 1 — Crear el entrypoint y los límites

Procedencia: E2, E3.

```text
trip-service/
├── cmd/
│   └── trip/
│       └── main.go
├── internal/
│   ├── domain/
│   ├── infrastructure/
│   │   └── repository/
│   └── service/
└── pkg/
    └── types/
```

## Fase 2 — Mantener `main` como punto de composición

Procedencia: E2.

```go
package main

func main() {
	// Las implementaciones se conectarán aquí en la siguiente lección.

```

## Código final completo de la lección

El árbol y `cmd/trip/main.go` son el estado recuperable. Los directorios vacíos pertenecen al generador del curso; en un proyecto propio conviene crearlos cuando reciban su primer archivo.

## Resumen mental

`cmd` arranca y compone; `domain` define el lenguaje y los contratos; `service` coordina; `infrastructure` implementa transportes y persistencia.
